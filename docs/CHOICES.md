# Engineering Decisions

## Why YOLOv8?

YOLOv8 provides:

- Real-time inference
- High detection accuracy
- Easy deployment
- Strong community support

---

## Why DeepSORT?

DeepSORT enables:

- Consistent customer tracking
- Unique identity assignment
- Reduced duplicate counting

---

## Why FastAPI?

FastAPI provides:

- High performance
- Automatic Swagger documentation
- Easy REST API development

---

## Why SQLite?

SQLite was chosen because:

- Lightweight
- No server setup required
- Suitable for challenge-scale workloads

---

## Why Event-Driven Design?

An event-driven architecture allows:

- Real-time monitoring
- Easy analytics generation
- Future scalability

---

## Tradeoffs

Current limitations:

- Local database only
- Single-machine deployment
- Limited anomaly detection

Future versions can use:

- PostgreSQL
- Kafka
- Redis
- Kubernetes
